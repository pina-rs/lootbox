# Release Process

The workspace uses monochange for versioned releases: a release PR is prepared from pending changesets, and merging it triggers trusted publishing to crates.io.

## Changesets

Any pull request that modifies code in a released crate must include at least one changeset file in `.changeset/`:

```sh
mc change --package lootbox_cli --bump patch --reason "describe the change"
```

Manual format:

```md
---
lootbox_cli: fix
---

# Short heading

Detailed description of the change.
```

## Change types

- `major` — breaking changes
- `feat` — new backwards-compatible features
- `fix` — bug fixes
- `docs` — documentation-only changes
- `none` — general notes

## Release flow

1. Push changesets to `main`. The `release-pr` workflow runs `monochange run release`, which opens or refreshes a `chore(release): prepare release` pull request.
2. Merge the release PR. On merge the same workflow tags the release, creates a draft GitHub release, and dispatches `publish.yml`.
3. `publish.yml` exchanges GitHub's OIDC identity for a crates.io token, verifies publish readiness, and publishes every changed package with `monochange step publish-packages --all` before marking the release as latest.

## First-time publication

crates.io trusted publishing requires the package to already exist on the registry. Before merging a release that introduces a new package:

1. Run `monochange step placeholder-publish --dry-run --package <package-id>`, then without `--dry-run` to reserve the name.
2. Configure the package's trusted publisher for repository `pina-rs/lootbox`, workflow `publish.yml`, and environment `publisher`.
3. Confirm the PR's publish job passes before merging.

## Packages

- `switchboard_randomness_cpi` — Pinocchio CPI helpers for Switchboard randomness
- `lootbox_sdk` — ergonomic Rust SDK over the generated client
- `lootbox_cli` — command-line client for every program instruction

The on-chain program and its generated client are never published: the program deploys through `pina build`, and the client is regenerated by `generate:clients`.
